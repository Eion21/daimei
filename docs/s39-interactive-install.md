# S39 interactive installation boundary

The NEW-only coordinator, persistent DENY hold, journal and Android transport are wired into the runtime. Public/release dispatch remains disabled; only the explicitly pinned `s39Qa` disposable fixture experiment can activate the bridge. Android signature verification and the complete native installation cycle remain **NOT VERIFIED**. Catalog and archive observations are not cryptographic verification or permission to execute code.

## Controlled path

An explicitly consented request reinspects the quarantined standalone APK, checks complete current signers and installed absence, journals the operation and persists a hold before creating a session. Streaming binds exact size and SHA-256; submission reinspects the request, package absence and owned session. Callbacks are correlated by operation, nonce and session; system confirmation needs a separate explicit decision. A correlated success and fresh installed package/version/full signer observation remain separate from execution consent and recognition. A guarded novel-only reload follows explicit execution consent; recognition is an observation, not a grant.

After a terminal rejected operation, a new consented request can rebind only its matching unreconciled DENY tuple, with a distinct operation and nonce, a matching terminal journal record and a fresh absent-package observation. Active, mismatched, uncertain, installed and private cases remain denied. The hold is never cleared or serialized as ALLOW. A streamed receipt is consumed before commit; process-local ownership is retained only for cleanup. An already absent committed owned session may be treated as cleaned up, but arbitrary abandonment failures remain failures. No session is adopted after process restart.

## Verification and limits

Previous QA compilation and focused JVM tests passed for the earlier candidate; they are not proof of this correction until rerun. JVM doubles do not prove Android Binder delivery, installer UI, certificate verification, ART loading or recognition on a device. The separately authorized native install/rejection/trust cycle and publication prerequisites remain pending. Public activation, updates and private-install migration remain disabled; S38 remains read-only. No phone operation or publication is authorized by these checks.
